## 2 · Architecture in one paragraph

The public site is static files: `src/pages/*.mjs` describe each page as data
and template literals, `build.mjs` renders them into `site/` with the CSS
inlined, assets content-hashed, and a link checker that fails the build if any
internal href does not resolve. Beside it, `automation/` is a PHP application
that owns everything dynamic: a MySQL database (23 tables, versioned schema,
migrations run automatically), an admin panel, JSON API endpoints, seven PHP
landing pages, the free audit tool, and a job runner driven by four hPanel
cron jobs (every 5 minutes, hourly, daily, weekly). The static pages carry
marker comments the panel writes analytics tags into. Both halves deploy from
one script that backs up first and rebuilds server-generated pages from the
database afterwards.

## 3 · Features, by area

### 3.1 · The public website

- **20 hand-written pages**: home, about, services index, 7 service pages
  (web development, SEO, social media marketing, CRM systems, business
  automation, AI visibility / GEO, technical support), work, contact, blog
  index, 3 hand-written blog posts, privacy, terms, 404, styleguide (noindex).
- **Design system**: paper/ink/marigold palette; Fraunces (display), Archivo
  (body), IBM Plex Mono (labels); self-hosted, subset WOFF2 fonts with
  metric-matched fallback faces (`size-adjust`, `ascent-override`) so a font
  swap never shifts layout. Fraunces is `font-display: optional` so the
  headline paints immediately.
- **Performance construction**: all CSS inlined (no render-blocking request),
  two fonts preloaded, nothing but text above the fold, the LCP element is the
  H1, HTML ~20KB over the wire. The motion stack (GSAP, ScrollTrigger,
  SplitText, Lenis) loads only on desktop with a fine pointer, after idle, and
  never under `prefers-reduced-motion`.
- **SEO**: unique titles ≤60 and descriptions ≤160 on every page, one H1,
  canonical, Open Graph and Twitter cards with a generated 1200×630 image per
  page, JSON-LD (`Organization` + `ProfessionalService` + `LocalBusiness` with
  NAP, `WebPage`, `BreadcrumbList`, `Service`, `FAQPage`, `Article`), XML
  sitemap with priorities, `robots.txt` that allows all AI crawlers,
  `llms.txt` / `llms-full.txt` for answer engines, 301s from every old URL,
  trailing-slash canonicalisation, HTTPS forced.
- **Accessibility**: axe-core clean on all pages (no critical or serious
  violations), skip link, visible focus states, keyboard-operable mobile menu
  that traps and returns focus, everything readable and navigable with
  JavaScript off.
- **Security headers**: HSTS, `X-Content-Type-Options`, `Referrer-Policy`,
  `X-Frame-Options: SAMEORIGIN`, `Permissions-Policy` (camera, microphone,
  geolocation, payment, USB denied), `Cross-Origin-Opener-Policy`, and a
  Content-Security-Policy covering `frame-ancestors`, `form-action`,
  `base-uri`, `object-src` (deliberately no `script-src`, so a tag added from
  the panel can never be silently blocked).
- **AI-crawler logging**: requests from GPTBot, ClaudeBot, PerplexityBot,
  Google-Extended and others are routed through `serve.php`, which logs the
  visit and serves the same file. Human traffic never touches PHP.
- **Own analytics**: a 2KB beacon (`wa.js`) posts page views to the server;
  visits are counted server-side, IPs truncated, no cookie. Works for the
  visitors who block third-party analytics.

### 3.2 · Contact form and lead capture

- Every form on the site posts to `/api/lead.php`, which **saves to MySQL
  first and emails second** — a mail failure never loses an enquiry. Answers
  JSON to `fetch()` and a readable page to a browser with JavaScript off.
- Validation server-side (name, email, message, whitelisted service chips and
  budget ranges), header-injection rejection, honeypot field, per-IP rate
  limit (default 10/hour, configurable), same-origin check, test-submission
  flag (`_test=<cron_key>`) that stores without notifying.
- **30+ fields captured per lead**: name, email, phone, company, services,
  budget, timeline (asap / 1–3 months / researching), has-site, site URL,
  message, page, referrer, UTM source/medium/campaign/term/content, click IDs
  (`gclid`, `gbraid`, `wbraid`, `msclkid`, `fbclid`), landing page, A/B
  variant, dwell seconds, pages seen, session hash, consent timestamp and
  **consent wording version** (stored with the lead so later edits to the
  text can never rewrite what someone agreed to), truncated IP, partial flag.
- **Partial leads**: a form abandoned after email/phone is stored, flagged,
  never notified and never enrolled — a recoverable record, not a contact.
- **Scoring**: points for budget, timeline, paid-click arrival, phone given,
  existing website, message length, company name, source, dwell; junk
  detection deducts. Banded hot / warm / cold with thresholds set in the
  panel (defaults 60 / 35). The lead page shows the exact reasons.

### 3.3 · Landing pages (`/lp/`)

- **Seven pages**: custom-crm, website-development, website-development-delhi,
  seo-ai-visibility, social-media, ecommerce, business-automation. One PHP
  controller, one data file per page, no site navigation and no fat footer
  (every removed exit is a retained visitor).
- **Message match**: `?kw=` / `utm_term` / `utm_campaign` looked up against a
  per-page whitelist to swap the sub-headline. The parameter is only ever an
  array key, never rendered — so it cannot become XSS. Unmatched keywords are
  logged for the owner to write a line for.
- **A/B variants**: optional variant B per page, split set in the panel,
  sticky per visitor for 30 days by cookie. The panel refuses to name a winner
  below ~30 enquiries per arm.
- **Multi-step form**: a plain three-fieldset POST form first; JavaScript adds
  the steps, progress and inline validation on top. Captures everything in
  §3.2 including click IDs.
- **Budget held**: PageSpeed mobile 100/100/100/100, LCP ~1.4s, CLS 0.002,
  with the analytics tags switched on. Server-side visit counting per page.

### 3.4 · Notifications on a new lead

- **Three independent channels, each wrapped so one failing cannot block the
  others**: the company mailbox, a personal address (currently the owner's
  Gmail), and Telegram.
- The email is a **decision-ready brief**: score band in the subject
  ("🔥 HOT lead — Name"), every field, the scoring reasons, and one-tap
  WhatsApp / call / open-in-panel buttons.
- Telegram: bot message with buttons; a hot lead not opened in the panel
  within N minutes triggers an escalation ping. Explains "chat not found"
  (the owner must message the bot first). Internal only — customers never
  see Telegram.

### 3.5 · Automated follow-up funnel

- **Three sequences** seeded from a reviewable data file: `hot` (5 steps,
  starts with an internal escalation to the owner), `standard` (8 steps),
  `nurture-light` (4 steps). 17 steps, 11 static fallback templates. Leads are
  enrolled by band.
- **AI-drafted messages** (Claude, Messages API via raw curl): the writer gets
  the lead's context and prior messages; every draft passes **quality gates**
  before it can exist: word count, exactly one call to action, link hosts
  allowlisted, no unfilled placeholders, no banned claims (invented clients,
  results, testimonials, "guaranteed" rankings — with a context check so a
  *warning* about guarantees is allowed), buzzword list, similarity against
  prior messages, must use the person's name. Two AI attempts, then the
  static template.
- **Human in the loop by default**: every AI message waits in the panel's
  approval queue, editable, with a Telegram ping. Auto-send is **opt-in per
  sequence**, never global, and audited with who switched it on.
- **Timing rules enforced in code**: business hours 09:30–20:00 IST Mon–Sat,
  quiet hours 21:00–09:00, Sundays and a configurable holiday list skipped,
  at most 1 message per channel per day and 2 per day per person, 45-minute
  minimum gap. A send scheduled inside quiet hours moves forward, never back.
- **Stop conditions** — any one halts the sequence immediately and cancels
  anything queued: the person replies (any channel), books a call, is moved to
  Meeting / Qualified / Won / Lost, opts out, has two hard bounces, or is a
  partial or test lead. A human replying from the panel also stops it.
- **Unsubscribe**: signed one-click link in every email (`List-Unsubscribe`
  and `List-Unsubscribe-Post` headers), plus replying "stop" / "unsubscribe"
  / "remove me". Sets do-not-contact across every channel.
- **Kill switch**: one button halts every sequence and cancels every message
  written but not yet sent; resuming picks up where things were. Sequences are
  also globally on/off (currently **off**).
- **Sender identity**: messages are signed by a named person and sent from a
  real mailbox with a `+lead<id>` reply address, which is how replies are
  matched.

### 3.6 · Conversations inbox

- **One thread per lead**, every message in and out on any channel, with
  status pills (queued, awaiting review, sent, failed, received, cancelled)
  and "AI written" marked.
- **Reply by email or WhatsApp** from the panel; sending records the message,
  moves a New lead to Contacted, and **stops the sequence**.
- **Ask Claude for a draft** — placed in the reply box, never sent by that
  button. Snippets paste at the cursor. Private notes are recorded and sent
  nowhere.
- **Inbound reply capture** (IMAP, every 5 minutes): matches a reply to a lead
  by the `+lead<id>` token, then by threading headers against a message we
  sent, then by sender address only when exactly one lead has it. Auto-replies,
  out-of-office and bounces are filtered. Quoted history is trimmed. A matched
  reply lands on the thread, adds score, and stops the sequence. Reads upward
  from a watermark so nothing is read twice and a backlog clears in a few
  ticks; unmatched mail is left unread for the humans. **Wired and verified on
  the live mailbox.**

### 3.7 · WhatsApp (built, switched off)

- Meta WhatsApp Cloud API direct, no BSP. **Utility category only** — a
  marketing template is refused in code, not discouraged. Session messages
  inside the 24-hour window are free-form; outside it only an approved
  template can reopen the conversation.
- **Monthly cap** (default ₹200) checked *before* every send, tracked in
  paise; at the cap the funnel falls back to email. Every sequence works with
  WhatsApp entirely absent. Cost meter on the Funnel page.
- Needs Meta business verification, a dedicated number and template
  approval; `WHATSAPP-SETUP.md` gives the honest case for and against.

### 3.8 · Free website audit tool (`/tools/free-website-audit/`)

- Visitor enters a URL, name, email (phone optional), ticks consent. The
  audit is queued and run by cron (30–90s), the visitor gets a self-refreshing
  "checking" page and a token URL, and the report is emailed.
- **17 checks against the real page**: HTTPS, compression, title and
  description lengths, Open Graph, H1 count, viewport and zoom, image alt and
  dimensions, structured data (walks `@graph`), ways to get in touch
  (tel / WhatsApp / form / mailto), HTML weight, server response time,
  third-party script count, `noindex`, canonical, `robots.txt`, sitemap, and
  Google's Core Web Vitals field data via PageSpeed. Weighted score;
  unmeasured checks are unscored, never faked. Headline names the heaviest
  problem. A good site is told it is good (wwwebtech.in scores 100, Zoho 86,
  a deliberately broken fixture 25).
- Report page (noindex) and HTML/text email. Each audit creates a lead with
  source `free-website-audit`; the owner is only alerted when the score is
  under 80. SSRF guard (no private ranges, no `javascript:`), 3 audits per
  host per day, per-IP rate limit, honeypot. Panel page lists every audit
  with resend / retry, and a "try it against any site" box that stores
  nothing.

### 3.9 · Ads feedback loop (offline conversions)

- Click IDs captured on every lead. Marking a lead Qualified or Won queues a
  conversion for Google and Microsoft.
- **Three CSV feeds** at `/api/conversions.php?type=google|microsoft|enhanced`
  behind a rotatable random key: Google offline conversion import (with the
  required timezone line), Microsoft offline conversions, and **Enhanced
  Conversions for Leads** for click-less leads (SHA-256 of lowercased email
  with Gmail dots stripped, and E.164 phone) — no readable contact detail
  ever leaves. Wrong or missing key → 404, never 403. `&mark=1` marks rows
  fetched so a human looking at the file does not consume the queue. Key
  generation and the URLs live on the Integrations page. `ADS-SETUP.md`
  covers the Google Ads side (not yet done — owner's task).

### 3.10 · Blog automation

- Scheduled generation (daily cron) from a topic queue of 90 seeded topics,
  under a **monthly spend cap** checked before the API call; measured cost
  shown in the panel (~13¢ a post).
- **Quality gates** before publishing: title ≤60, description 120–160,
  minimum H2 sections, no H1 in the body, banned-claim regexes (with the
  warning-context exception), similarity against recent posts, FAQ block.
  Rejections are logged with the reason.
- Published posts are written into `site/blog/<slug>/` from the same page
  shell as the hand-written pages, teasers injected into the blog index
  between markers, sitemap updated, IndexNow pinged. **Rebuilt from the
  database after every deploy**, so a redeploy of the static site never
  loses a generated post. Manual "Write one now", publish / take down, and
  topic management in the panel. **8 posts live**, 2 of them published
  unattended since this morning.

### 3.11 · SEO automation

- **Daily**: title and description lengths on every URL in the sitemap,
  homepage structured data, every sitemap URL returns 200, sitemap referenced
  from robots, AI crawlers allowed and `llms.txt` present, security headers
  and compression, PageSpeed Core Web Vitals (mobile and desktop) recorded to
  a history table, homepage reachability. 8/8 passing on production.
- **Weekly**: a full crawl and deeper checks (5).
- `llms.txt` and `llms-full.txt` regenerated from the database; IndexNow
  submission on publish; the panel's SEO Health page shows every check with
  its finding and history.

### 3.12 · Integrations (tag manager)

- Paste-an-ID support for GA4, Google Tag Manager, Google Ads conversion tag,
  Meta Pixel, Microsoft Clarity, Search Console and Bing verification, plus
  two free-form slots. Each shows its **measured** page-weight cost and
  whether it sets cookies; the page warns that switching one on creates a
  consent obligation and points at the privacy policy.
- **Applied to the whole site**: written between marker comments in every
  static page (idempotent, and removal restores the page byte-for-byte), and
  rendered at request time on the PHP pages.
- **Deferred loading**: every script tag waits for the visitor's first touch,
  scroll or keypress, or five seconds after `load`. `gtag()` calls made before
  then are queued and replayed; GA4 and Ads share one `gtag.js` download.
  This took the homepage from 80 to 100 on PageSpeed. Currently on: GA4
  (`G-L0NEHDTSN4`), Tag Manager (`GTM-PKLJQGLN`), Ads (`AW-18257783835`).
- "Check they are live" verifies against the real homepage over HTTP.

### 3.13 · Admin panel (`/admin/`)

14 pages: **Dashboard** (KPIs, unactioned leads, job heartbeat with last run
and status per job, one-click "run now" for any job), **Leads** (filter,
search, pipeline counts, bulk status, CSV export of exactly the filtered set,
score and band column), **Lead** (everything captured, scoring reasons, full
timeline of every event, automation state with a stop button, status and
notes, resend notification), **Analytics** (visits, sources, pages, devices,
countries, bots, per-page — all server-side), **Conversations**,
**Funnel** (kill switch, KPIs, WhatsApp meter, approval queue, active
enrolments, per-sequence review switch), **Landing pages** (visitors,
enquiries, rate, hot, won, abandoned per page; A/B comparison; unmatched
keywords), **Audits**, **Blog**, **SEO health**, **Integrations**,
**Connections** (see 3.18), **Settings**, **Login**.

- **Accounts and roles**: admin and read-only viewer; first-run setup that
  closes itself once an account exists; password change; **TOTP two-factor
  authentication**; login lockout; session hardening.
- **Every mutation is a POST with a CSRF token**; viewers cannot reach write
  actions; an **audit log** records who changed what.
- **Settings**: mailbox (SMTP, from name, recipient, reply promise,
  acknowledgement toggle, send-me-a-test), follow-up and scoring (sender
  name and address, alert address, hot/warm thresholds with the live lead
  split, review ping, consent wording), Telegram (token, chat id, test),
  WhatsApp (token, phone id, cap, on/off, spend), reading replies (IMAP host,
  port, mailbox, password, check now), data retention, analytics on/off.
- Secrets (API keys, tokens, passwords) are **AES-256-GCM encrypted at rest**
  with the key in `config.php`, outside the database and the web root.
- Own Content-Security-Policy, all pages render against the production
  database (verified 13/13).

### 3.14 · Security

PDO prepared statements only (emulation off); every raw interpolation is a
literal and marked `SAFE-SQL`; secrets encrypted at rest; CSRF on every
mutation; roles; TOTP; rate limits on the form, the audit tool, the
conversions feed and login; honeypots; same-origin checks on POSTs; header-
injection rejection; the message-match parameter never rendered; SSRF guard
in the audit tool; conversions key compared with `hash_equals`, never logged,
404 on failure; IPs truncated before storage; private folder outside the web
root with `.htaccess` denials; deploy refuses to ship a bundle containing a
key or a development password; security gate of 64 static checks including
"no unescaped output".

### 3.15 · Deployment and operations

- `tools/deploy.sh`: timestamped backup of the live site, rsync with
  `--delete` and an **exclusion list that is checked against the automation
  web root** (refuses to run if a server-managed directory would be deleted —
  this bug had happened twice before the guard), post-deploy verification of
  key URLs and redirects, then `republish_all` rebuilds generated pages and
  re-applies tags. `--dry-run` and `--rollback`. Deploy target in a gitignored
  `tools/deploy.env`.
- **Four cron jobs** (hPanel): every 5 minutes (`funnel_tick`, `inbox_poll`,
  `audit_run`), hourly (analytics roll-up plus the same three), daily
  (analytics prune, blog, SEO), weekly (SEO crawl). Jobs run in-process
  (`exec` is disabled on the host), raise their own time limit, and record
  start / end / status / error in a heartbeat table the Dashboard shows.
- `selftest` job runs every query against the real production database
  (caught a MariaDB 11.8 incompatibility once). Transparent reconnect when
  the host closes an idle MySQL connection during a long API call.
- Schema migrations run automatically on first request after a deploy
  (currently v5).

  and "STOP" opts them out — exactly as email replies do.

  configured connection; a Connected → Error transition alerts on every
  channel that still works, lights a dot on the nav item and a line on the

- **Migration v6** moved the mailbox password and the test key out of
  `config.php` into the encrypted store; `config.php` now holds only the
  database login, the encryption key, salts and paths. Restoring a backup on

- Verified by `tools/gate-connections.sh` and `tests/connections_test.php`;
  the security gate gained assertions that no page echoes a secret and no
  log line is handed one.

## 5 · Known limitations and open decisions

- **Cookie consent banner**: the site sets cookies via Google's tags and the
  policy says so; whether the DPDP Act warrants a banner is the owner's call.
  If wanted, it gates the deferred loader — a one-line change.
- **Two GA4 properties exist**; only `G-L0NEHDTSN4` receives data.
- **Google Ads** conversion actions and scheduled imports are not yet set up.
- **No `script-src` in the CSP** by design, until the set of tags settles.
- **Core Web Vitals field data** does not exist yet (not enough traffic); all
  speed figures are lab.
- **Credentials**: several were pasted into chat transcripts during the build
  and should be rotated (mailbox, SSH, database, Anthropic key, PageSpeed
  key). A deploy SSH key exists so passwords need never be shared again.
